# BYDMate Remote Climate — первый этап

Мобильный кабинет: **https://byd.slk-soft.ru**. Сервер принимает только настройки климата; произвольных shell/ADB-команд, открытия дверей и запуска автомобиля нет.

## Подключение

1. Администратор создаёт одноразовое приглашение, действующее 7 дней:

   ```sh
   ssh hixman@212.164.59.22 'sudo docker exec bydmate-remote python server.py invite'
   ```

2. Пользователь открывает ссылку, вводит почту и пароль (12–128 символов). Почта служит логином: SMTP, подтверждение почты и самостоятельное восстановление пароля пока не реализованы.
3. В новой сборке BYDMate: **Настройки → Удалённое управление → Подключить машину**. Отсканировать QR камерой телефона, войти в кабинет, подтвердить привязку. QR действует 10 минут, привязывает машину только один раз. QR нельзя передавать посторонним.
4. Задать название автомобиля, климат и сезонные правила, сохранить. Можно привязать несколько автомобилей.

## Поведение

- Опрос сервера машиной каждые 15 секунд, исходящие HTTPS-запросы; входящие порты на автомобиле не нужны.
- «При запуске» выключено по умолчанию. При включении: одно применение на запуск TrackingService после готовности ADB и получения свежих данных автомобиля, а не каждую минуту. Сохранение настроек само по себе не выдаёт немедленную команду.
- «Применить сейчас» использует сохранённые основные настройки, выдаёт задание на 15 минут и заменяет предыдущие ожидающие задания. Если машина офлайн, задание ждёт её подключения до истечения срока. Выключенную машину сервер не будит.
- Автоматические зимнее/летнее правила работают при запуске: зима при `температура ≤ порог`, лето при `температура ≥ порог`, иначе основные настройки. Зимний порог должен быть ниже летнего. При активных правилах без реального показания внешней температуры запуск ждёт это показание.
- Температура 16–33 °C, обдув 1–7, подогрев каждого переднего сиденья 0–3. Фактическая поддержка зависит от комплектации. При выключенном климате температура и обдув не меняются; подогрев сидений задаётся независимо.
- Выполнение только при известной скорости 0 и передаче P, живом источнике данных и образце не старше 30 секунд. Это проверяется перед каждой командой.
- Результат каждой команды виден в кабинете и отправляется в настроенный в машине Telegram. «Команда принята» не означает аппаратное подтверждение всех параметров; обдув на DiLink2 использует существующую проверку чтением обратно.
- Журнал на машине записывается до аппаратных команд. При остановке приложения посередине результат «неизвестен», автоматического повторения нет. Потеря сети после выполнения повторяет передачу результата, а не команды.
- GPS показывается с временем реальной последней фиксации. Отсутствующая GPS-фиксация не превращается в `(0,0)` и не стирает последнюю точку. Встраиваемый виджет передаёт координаты Яндекс Картам; ссылка позволяет открыть их в приложении.
- Локальные автоматизации BYDMate остаются активны и могут менять те же параметры; избегайте противоречащих климатических правил.
- На машине можно запретить удалённое управление переключателем. В кабинете «Отвязать» снимает владение, отменяет ожидающие задания и сбрасывает серверные правила.

## Развёртывание и aaPanel

- Хост: `212.164.59.22`, Compose-проект `bydmate-remote`, контейнер `bydmate-remote`.
- Исходники и Compose: `/www/server/panel/data/compose/BYDMate-Remote/compose.yaml`.
- Docker-сервис публикуется **только** на `127.0.0.1:18183`; наружу работает nginx HTTPS.
- База SQLite/WAL: именованный Docker-том `bydmate-remote_bydmate-data`, файл `/data/bydmate.db` внутри контейнера. Не удалять том при обновлении. Для согласованной копии использовать SQLite backup API, а не копирование одного `.db` при работающем WAL.
- aaPanel: сайт `byd.slk-soft.ru` зарегистрирован в списке сайтов, Compose зарегистрирован в Docker → Compose. Регистрационные скрипты сохраняют резервные копии баз панели перед добавлением записей и не перезаписывают чужие проекты.
- nginx: `/www/server/panel/vhost/nginx/byd.slk-soft.ru.conf`; сертификат: `/www/server/panel/vhost/cert/byd.slk-soft.ru/`. Сертификат выпущен встроенным ACME aaPanel; порядок обновления сохранён в панели. На сервере уже есть задача aaPanel `acme_v2.py --renew_v3=1`.
- Docker работает от непривилегированного UID, root filesystem read-only, capabilities сняты, логи ограничены. Пароли scrypt, сессии и ключи устройств хранятся только хешами на сервере; Android-ключ устройства шифруется AndroidKeyStore. Cookie Secure/HttpOnly/SameSite, проверка Origin, лимиты попыток регистрации/входа.

Обновление после копирования изменённых файлов:

```sh
sudo docker compose --project-directory /www/server/panel/data/compose/BYDMate-Remote \
  -f /www/server/panel/data/compose/BYDMate-Remote/compose.yaml up -d --build
sudo docker logs --tail 50 bydmate-remote
curl --fail https://byd.slk-soft.ru/health
```

Первичное развёртывание: сначала `deploy/nginx-http.conf`, проверка/reload nginx, `deploy/issue_certificate.py` через Python aaPanel, затем `deploy/register_aapanel.py`, HTTPS-конфигурация и `deploy/register_compose.py`. Скрипты сертификатов не выводят закрытые ключи.

## Проверка

```sh
python -m venv /tmp/bydmate-test-venv
/tmp/bydmate-test-venv/bin/pip install -r remote-control/requirements.txt
/tmp/bydmate-test-venv/bin/python -m unittest discover -s remote-control -v
./gradlew :app:testDebugUnitTest :app:assemblePhysicalDebug
```

`deploy/qa_smoke.py` создаёт только одноразовый QA-аккаунт и две симулированные машины, проверяет публичный HTTPS API. Никаких реальных автомобильных команд не отправляет. `deploy/qa_cleanup.py` удаляет только этот строго проверенный тестовый набор, сохраняя SQLite-снимок. На реальном DiLink2 выполнение климата и доставка отчёта в Telegram требуют отдельного стендового испытания новой APK.

Это первый этап, не готовый массовый сервис: перед открытием широкой аудитории нужны регулярные резервные копии, администрирование пользователей/восстановление доступа, контроль эксплуатации и проверка на автомобиле. В APK 3.9.0 функция опубликована как экспериментальная и выключена по умолчанию; установка на физическую машину требует отдельной проверки.
